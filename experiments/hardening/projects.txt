# Sertleştirme Blok 1 — referans proje seti
#
# Metrik doğruluğu bu projelerde ölçülür. Her satır bir commit hash'ine
# dondurulmuştur: tag taşınabilir, hash taşınamaz. Sonuçlar bu hash'ler için
# geçerlidir; set değişirse `metric-accuracy.md` yeniden üretilir.
#
# Biçim (boşlukla ayrılmış):
#   ad  github-deposu  tag  commit  kapsam-dizini  [dışlanan-dizin ...]
#
# Kapsam dizini, taramanın başladığı yerdir (`rlens scan <kapsam>` gibi).
# Dışlananlar kapsama göre görelidir. Test dizinleri dışlanır: ölçmek
# istediğimiz ürün kodudur, test kodu farklı bir deyimle yazılır.
#
# Seçim kriterleri — tek eksende değil, üç eksende çeşitlilik:
#
#   Boyut:  requests, click (küçük) → rich, flask, attrs (orta)
#           → sqlalchemy/orm, mypy, pandas/core (büyük)
#   Stil:   annotation'sız eski kod (requests) → yoğun annotation (httpx,
#           pydantic, black, mypy); dekoratör ağırlıklı (click, attrs,
#           fastapi); metaclass ve descriptor (sqlalchemy, pydantic);
#           `@overload` yoğun (sqlalchemy, pandas, pydantic)
#   Deyim:  HTTP istemcisi, terminal çıktısı, doğrulama, web çatısı, sınıf
#           üreteci, CLI, ORM, biçimlendirici, tip denetleyici, veri çerçevesi
#
# `pandas/core` doküman önerisindeki "frame.py çevresi"nin dizin karşılığıdır:
# tek dosya CC için yeter ama kohezyon ve DCC için sınıf sayısı ince kalır.
# `pydantic/v1` eski sürümün gömülü kopyasıdır ve dışlanır; aynı kodu iki kez
# saymak dağılımı eğer. mypy'nin kendi test paketi `mypy/test` altındadır.
#
